# SDD Project Workflow

Use this skill only through the machine-local `.sdd-runtime/agent-guide.md`
generated by `install-sdd.sh` after it detects an installed adoption manifest.

## Execution

1. Read the complete guide and verify its project root, playbook checkout Git
   origin, and resolved revision against the manifest. Treat the checkout as
   read-only. On any mismatch, make no project edit and report `BLOCKED`.
2. Read the project entry point, manifest, active project contracts, and the
   project-owned solution whiteboard.
3. If the installed integration has no solution whiteboard, instantiate an
   empty one at the guide's recorded adoption root and stop after applicable
   checks. Do not infer a need merely to fill the template.
4. When the whiteboard already exists, follow its state and instructions. The
   need, facts, requirements, proposals, corrections, and conclusion belong in
   the whiteboard rather than in the installation guide.
5. Preserve independent review gates and exact allowed write scopes. Generate
   no downstream handoff or delivery artifact until the whiteboard convergence
   and review gates authorize it.
6. Preserve unrelated and user-owned work, and report exact checks and evidence.

The installation guide is runtime orchestration data, not project authority.
The reviewed manifest and linked project contracts remain authoritative.
